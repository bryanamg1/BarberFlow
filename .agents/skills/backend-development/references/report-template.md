# Backend Delivery Report

Adapt this guide to the change. Omit irrelevant sections and replace guidance with actual results. Keep a small delivery report short.

## Delivered behavior

State the implemented outcome and the acceptance criteria it satisfies. Identify any partially implemented or blocked behavior explicitly.

## Contract and intentional changes

Summarize affected endpoints, services, jobs, or integrations and the purpose of changed files. Mention input, response, error, access, or event-contract changes only where relevant.

## Consistency and compatibility

Describe relevant ownership or tenant restrictions, persistence invariants, transaction boundaries, and handling of duplicate or external effects. Mention migration or consumer compatibility requirements when the change introduces them.

## Validation

List only checks actually executed, their result, and any relevant environment limitation. Distinguish added test coverage from tests that ran successfully. Mark proposed or unavailable checks as not run; do not treat an unavailable integration check as passing.

## Configuration and documentation

Describe actual new configuration, dependencies, API documentation, or operating requirements. Do not include credentials or sensitive values. Omit this section when nothing changed.

## Remaining risks and next action

State unresolved assumptions, unverified boundaries, or blocked criteria and their impact on completion. Identify a concrete next step when further work is necessary; otherwise state that no additional action is required within the implemented scope.
